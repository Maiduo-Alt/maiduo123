## 1. 在线模拟接待（9.1 第 1 条 / 9.2 场景 1、2、5）

> 自由练习只对管理员/主管开放（客户新增需求），所以这一节用 **`leader` 或 `admin`** 验收；
> 客服的训练路径见第 1.5 节。

1. 用 `leader` 登录 → 左侧「在线模拟接待」→ 选 **L1** 点「开始接待」。
2. **应看到**：买家约 2 秒后进线推第一条问题；顶部标题栏显示 `L1 话术适应 / 剩余会话 / 已用时长`；消息区是「头像 + 昵称 + 时间 + 气泡」，客服消息靠右。
3. 在输入框回一句正常话术（例：`亲，您好，很高兴为您服务，我马上帮您核实一下～`）→ 按 Enter 发送。
4. **应看到**：回复右侧出现「响应 Ns」；若是命中要点的回复，气泡下方还会出现「命中要点 N 项」。
5. 切到右上角「商品」页签 → 看「咨询宝贝」卡片与动作按钮；点「发送商品卡片」→ 输入框出现商品卡片文本。
6. 点工具栏的「快捷短语」→ 右栏切到快捷短语列表 → 点一条 → 输入框插入内容（含 `{变量}` 的会按当前会话替换商品名/价格/订单号）。
7. **计时与超时**：故意不回复，等倒计时归零 → 队列项计时变红、出现超时提示音；明细里会记一次超时。
8. **断线续接**：接待中刷新页面，或切到「我的训练」再点回「在线模拟接待」→ **应看到**顶部黄色提示「你有一次进行中的接待」，点「继续接待」回到原来的局。
9. 点左下「结束本次接待并生成评分」→ **应看到**结果弹窗（接待总分 / 结论 / 各会话四维得分），并有「查看明细与逐条复盘」入口。

### 1.5 客服侧的入口收敛（客户新增需求）

1. 用 `agent` 登录 → 左侧训练中心**只有**「我的训练 / 我的任务 / 模拟接待明细」，**没有**「在线模拟接待」。
2. 首页 **看不到**「难度档位与快速开始」，只有一张「开始训练」提示卡 + 「去我的任务」按钮。
   （带教/管理员首页同理：没有难度卡，也**没有**任何提示卡，只留「我的任务」「我的最近接待」「成长曲线」——
   客户 2026-10-03 下午要求把「自由练习已统一放在《在线模拟接待》里」那张卡整块删掉。）
3. 直接访问旧链接 `/reception`（不带参数）→ 看到引导页「从《我的任务》进入训练」，不会出现难度卡片。
4. 从「我的任务」点「开始训练」→ 正常进入任务训练（右栏有任务卡）。
5. 直接调接口 `POST /api/receptions {source:'free'}` 也会被拦（返回 1003），不是只在界面上隐藏。

### 1.6 接入人数与解锁条件（客户新增需求）

1. `admin` →「系统参数」→「难度与接待参数」：能看到 **L1～L4 各自的接入人数**（默认 1/2/3/4）。
   把 L1 改成 3 → 保存 → 用管理员开一局 L1，**应接入 3 名买家**；把「并发接待上限」压到 2，L1 就只接 2 人（取 min）。
2. 「解锁下一档所需达标次数」默认已是 **1**：客服做一次任务训练并达标后，`GET /api/receptions/levels` 里下一档变 `unlocked: true`。
3. **难度逐步解锁是强制的**（2026-10-02 修复）：客服只解锁 L1 时，即使任务允许 L3，也开不了——
   界面上 L3/L4 显示`未解锁`且按钮禁用；直接调接口会返回 **1003**「L3 进阶 还没解锁：先在同一档位达标 1 次解锁下一档，或让带教在《账号》里为你开放难度」。
4. 解锁的两条路：① 在上一档达标 1 次自动解锁；② `admin`/`leader` 在「账号」页用「开放难度」直接勾选（接口 `POST /api/accounts/:id/unlock-levels`）。

### 1.7 本次模拟总接待人数（客户新增需求 C5）

1. `admin` →「系统参数」→ 第二组「L1～L4 总接待人数」：**默认 10 人**（客户 2026-10-03 确认），
   四个框里预填的就是 10；清空提交也会回到 10（不再回落到接入人数）。
2. 把 **L2 总接待人数改成 5**、接入人数保持 2 → 保存 → 用管理员开一局 L2。
3. **应看到**：开局只接入 2 名买家，左栏「**接待买家 2** / 正在接待 2 / **剩余会话 3**」——
   接待买家是**累计已进线**（客户 2026-10-03 对齐赤兔火眼口径），不含还在排队的；
   「正在接待」页签里只有这 2 个人，另外 3 个在「**待接入**」页签里、带`待接入`标签。
4. 点某个在接待会话的「结束会话」→ **应看到** 待接入 3→2，并且**几秒内**就补进 1 个新买家
   （正在接待始终顶在 2 人）——这就是赤兔那套「**空位即补**」。
5. 点「结束本次接待并生成评分」→ 5 个会话全部进终态（总量全部接待完才算结束）。
6. 待接入的买家**点不出回复**：对它发消息会提示「该买家还在排队待接入」。

### 1.8 管理员开局时当场指定本局人数（C5，2026-10-02 追加）

1. 用 `admin`（或 `leader`）登录 →「在线模拟接待」→ 每张难度卡上多了两个输入框：**「本局接入 N 人 · 合计 M 人」**。
   默认值就是当前生效值（留空兜底后的结果）。
2. 把 L2 改成「本局接入 1 人 · 合计 3 人」→ 点「开始接待」。
3. **应看到**：左栏「接待买家 1 / 正在接待 1 / 剩余会话 2」，队列里 2 个`待接入`；
   结束接入中的那个，**几秒内**第 2 个买家就补位进线（接待买家 1→2）。
4. 这个覆盖**只写进这一局的参数快照**：不改系统参数、不影响别的局；补位、服务重启恢复、历史复盘都按这一份算。
5. 客服（新人）不能自己指定：任务训练的开局界面没有这两个框，直接调接口带 `totalCount` 会返回 **1003**。

### 1.9 成长曲线的口径（2026-10-02 按反馈调整）

1. 首页「我的成长曲线」**默认按「当天每次模拟」**：横轴是每局的开始时间（HH:mm），一个点就是一局，
   卡片标题显示「今天 N 次模拟」；这样一天练几局就能看出走势（按天平均对新人只有一个点）。
2. 卡片右上角可切到「最近 30 天」→ 回到按天平均的口径（方案 F2-09 原文）。
3. 两个粒度都能切「总分 / 首响时长 / 超时次数」三个指标；底部文案会相应显示「今天共 N 次」或「30 天共 N 次」。
4. 带教可在明细页按客服筛选后，用同一张曲线看某个新人的当天节奏。

### 1.10 订单卡片：售前 / 售后以「发货」为节点（客户新增需求 C8，2026-10-03）

对照客户给的三张参考图（待付款 / 待发货 / 已发货）逐步看：

1. `leader` 登录 →「在线模拟接待」→ 选一张**售前**难度的卡开局（第一问通常是价格/商品/会员类）→
   点右栏「**订单**」页签 → **应看到「待支付」卡片**：订单号、商品、规格、**订单金额 / 下单时间**、
   收货信息，底部按钮是「核对地址 / 催付 / 改价 / 改地址」（平台侧写操作是禁用占位）。
2. 回一句让买家推进到下一条问题；当买家问的是**发货/物流/时效**时 → 订单卡片变成「**待发货**」：
   实付金额 / 付款时间 / **承诺发货倒计时**，规格下方出现「代客发起售后 / 发售后卡」，
   底部按钮是「核对地址 / 改地址 / 去发货 / 发货协商」。
3. 换一张**售后**难度（L3/L4）开局，或让买家问到退货/退款/投诉这类问题 →
   **应看到「已发货」卡片**：承诺送达 / 发货方式 / **物流信息（快递 + 单号 + 已签收时间）/ 发货时间**，
   底部按钮是「发物流卡 / 改地址」。
4. 买家消息头上有 **售前 / 售后** 标签，和订单状态是**同一份数据**：售后问题一定配「已发货」订单。
5. 卡片里每行的「**发送**」是真行为：点一下会把那一行内容插进输入框（例如「规格：浅蓝色 / M」）。
6. 同一局里订单是**同一笔**：反复推进问题时，订单号、金额、下单时间保持不变（只有状态与字段在推进）。
7. 想直接出三张图对照参考图：`node tools/order-shots.mjs` → `docs/截图/unpaid-待支付.png`、
   `unshipped-待发货.png`、`shipped-已发货.png`。

### 1.11 平台侧操作「点击后记为一次业务动作」（客户新增需求 C10）

1. 在《在线模拟接待》里点开右栏「订单」页签上的任意一个动作按钮（**待支付**卡片上是
   `核对地址 / 催付 / 改价 / 改地址`；**待发货**是 `核对地址 / 改地址 / 去发货 / 发货协商` +
   规格下方的 `代客发起售后 / 发售后卡`；**已发货**是 `发物流卡 / 改地址` + `代客发起售后`）。
2. **应看到**：右上角提示「已记为一次业务动作：催付，标准话术已发给买家」，对话区随即出现一句标准话术，
   该条气泡下方标着 `业务动作 · 催付`。
3. 再点一次同一个动作 → 依然记录成功（**不会**被判「无效 / 敷衍回复」，这是正常操作）。
4. 换一个和当前订单状态不匹配的动作（例如待支付的订单点「去发货」）→ 接口会用 1001 拒绝并说明原因
   （界面上该按钮本来就不会出现在这一态）。
5. 复盘：结束接待后进「模拟接待明细 → 会话回放」，描述区有一行「业务动作（N）」，逐条列出点过的动作，
   回放里对应消息也标着 `业务动作：催付`。

> **明确不做**：改价、催付、去发货、修改地址等**平台侧写操作不接**（不会真的改平台数据），
> 训练环境只还原工作台的样子，点了记为一次业务动作并发出对应的标准话术。

### 1.12 会话页对齐飞鸽 + 商品「规格/属性」（客户新增需求 C13，2026-10-03）

1. `leader` 开一局 → 对话区首条「咨询宝贝」就是**飞鸽式商品卡**：商品图、标题、价格、库存、

### 1.13 推送问题按比例混合售前 / 售后（客户新增需求 C14，2026-10-03）

1. `admin` →「系统参数」→「**问题构成（售前 / 售后）**」：有一个「**售后问题占比（%）**」，默认 **20**，范围 0～80。
2. 保持默认开一局 → 挨个看买家的提问：**大部分**是「还没有订单、只咨询商品信息」的问题
   （面料/颜色/尺码/优惠/多久能到……），**小部分**是「**买完商品后**」的订单类问题
   （改收货地址 / 改快递 / 催发货 / 改单 / 改电话 / 备注配送）。开场那一问一定是剧本自己的话题。
3. 看右栏「订单」卡片：**催发货 / 改地址 / 改快递**这类问题配的是「**待发货**」（货还没发出去），
   而**物流 / 签收 / 退换 / 质量**这类配的是「**已发货**」。
4. 把占比改成 **0** 再开一局 → 整场都是剧本本身的话题，一个问题都不换；
   改成 **50** → 大约一半轮次变成订单类问题（实现上最多换一半，保证「大部分」还是原话题）。
5. 越界校验：填 90 保存会被拒（提示 0～80）。

### 1.14 任务按商品种类下发 + 问题与商品一致（客户新增需求 C15，2026-10-03）

1. `leader` 登录 →「回复模拟任务」→「下发任务」→「**剧本范围**」选「**按商品种类（男装/女装…）**」→
   在「选择商品种类」里挑（例如「女装（122 个剧本）」）→ 下发。
2. 用被下发的客服登录 → 从《我的任务》开始训练 → 挨个看买家提问：
   **抽到的商品都属于所选品类**（右栏「咨询宝贝」与对话区商品卡上的商品ID/分类对得上），
   问题也不会串品类（选女装不会出现鞋码、保质期、保修这类词）。
3. 想看别的品类就把范围改成「鞋靴 / 箱包 / 食品 / 数码 / 母婴…」（商品库 13 个品类都有剧本）。
4. 选一个**没有剧本**的品类（或手填不存在的品类）→ 开局会明确提示
   「任务限定的商品种类下还没有可用剧本，请让带教调整任务范围或先补充该品类的剧本」。
5. 一致性是**机器守着**的：`npm run test -w backend` 里的 `product-consistency.spec.ts`
   会全量扫描内容库与题库，出现「问题与商品不匹配」直接测试失败。

### 1.15 下发任务时「剧本 + 商品」同时多选（客户新增需求 C16，2026-10-03）

1. `leader` →「回复模拟任务」→「下发任务」→「剧本范围」选 **「指定剧本 + 商品（都能多选）」**。
2. **应看到**两个多选框：「选择剧本（可多选）」「选择商品（可多选）」——两个都选 = 只抽
   「这批剧本里、关联了这些商品」的；任一侧留空 = 该维度不限制（只选剧本≈指定剧本清单，只选商品≈按关联商品）。
3. 用被下发的客服开局：抽到的商品一定在所选商品里。
4. 故意选一组**不可能同时满足**的组合（剧本 A + A 没关联的商品）→ 开局提示
   「任务限定的「剧本 + 商品」组合下没有可用剧本，请让带教调整任务范围」——
   不会随便抽一个别的剧本或商品糊弄过去。
5. 附带：在《客户问题剧本》里「批量生成」时，如果所选商品和某条咨询内容不匹配（例如内容是「鞋码」但选的是女装商品），
   这条内容会被**跳过**并提示原因；单个创建时则直接报错。
6. **任务列表里能看到范围**：新增「范围」列，显示成 `剧本 2 个 × 商品 3 个` / `商品种类：女装、男装` /
   `剧本分类：售后` / `关联商品 3 个` / `剧本清单 2 个` / `全部剧本`；鼠标悬停能看到具体选了哪些剧本/商品。

### 2.5 无效 / 敷衍回复判定（客户新增需求 C6）

1. `admin` →「系统参数」→「无效 / 敷衍回复判定」：**总开关默认关闭**（关闭时行为与改造前完全一致）。
   页面会提示「官方只公布三种情形、没有公开词表，下面的词表属业务方自定义口径」。
2. 打开总开关、判定方式选「与上一条完全相同」→ 保存 → 开一局接待。
3. 对同一个买家**连发两条一模一样的话** → **应看到**：第二条发出后立刻弹出警告「该条回复被判为无效回复：与上一条回复完全相同」，
   该条消息下方出现红色`被判无效回复`标签（悬停看依据），并且它**没有**「响应 Ns」。
4. 换个说法正常回复 → 该轮时长按「买家发消息 → 首条有效回复」计算（官方回退口径）。
5. 换成「连续 N 次完全相同」+ 阈值 3 → 连发 3 条相同内容时第 3 条才判无效。
6. 在词表里加一个词（例如`不知道`）→ 回复里带该词即判无效；词表与「禁用词库」是两套，互不影响。
7. 「模拟接待明细」：列表出现`无效回复`列；筛选条「判定标签 = 含无效回复」能筛出这一局；
   进入详情，回放里该条消息会标注「被判无效回复：<依据>」。
8. **平均响应口径**：故意漏回一轮（或某轮始终没答到要点）→ 明细里平均响应会把这一轮按 **600 秒**计入，
   而不是按只算已回复轮次。

## 6. 账号（9.1 第 6 条）

## 8. 回复模拟任务（二期，但已做完）

用 `leader` 下发、`agent` 执行：

7. **全部达标后任务自动完成（方案 F6-08）**：把一个任务下发给两名客服、需完成 1 次，只有 1 人达标时任务仍是「进行中」、
