# 1 项目概述

## 1.1 编制背景

在线客服是电商店铺承接转化与售后口碑的第一道关口。新入职客服在上岗初期普遍面临"没有安全练习环境"的问题：真实客户不能承受试错成本，老带新又高度依赖带教个人经验，导致新人上手周期长、话术风格不统一、面对多客户同时进线时手忙脚乱。

本系统面向刚入职的在线客服人员，构建一个"可反复试错、可量化评估、可复盘改进"的模拟接待训练环境。系统以抖店客服工作台为界面与计时规则蓝本，让新人在与真实工作台高度一致的场景中练习在线客户回复，同时把每一次训练的接待过程完整记录下来，形成可回看的训练档案。

当前阶段存在的主要痛点归纳如下：

- **试错成本高**：新人直接接待真实客户，话术不熟、响应不及时会直接影响店铺体验分与转化。
- **带教不可规模化**：一名带教同时只能盯少量新人，且无法覆盖"多客户并发"这类高压场景。
- **场景不可复现**：真实客户的问题类型、情绪强度、追问节奏随机，新人很难系统性地练到全部高频场景。
- **缺少量化依据**：新人"练得怎么样"依赖带教主观看感，没有统一的评分口径与达标线。
- **素材散落**：优秀接待案例、商品资料、常见问题散落在聊天记录与个人笔记中，无法沉淀为可训练、可复用的资产。

## 1.2 建设目标

总体目标：把"新人独立上岗"从依赖个人经验的过程，转变为可配置、可复现、可量化、可考核的训练过程。

具体目标如下：

- **练得真**：接待界面、计时口径、会话切换方式贴近抖店客服工作台，训练成果可直接迁移到真实工作。
- **练得全**：通过剧本库覆盖售前咨询、售后处理、物流、发票、优惠、价保等高频场景，并按难度逐级加压。
- **练得准**：每次接待自动生成评分报告，包含响应时效、问题解决率、话术规范、情绪安抚四个维度。
- **练得住**：支持多客户并发接待，训练新人在压力下的优先级判断与话术组织能力。
- **练可管**：带教可下发训练任务、查看明细与统计，形成"布置—训练—评分—复盘"的管理闭环。

量化目标（一期上线后 3 个月内衡量）：

| 指标 | 现状基线 | 目标值 | 衡量方式 |
| --- | --- | --- | --- |
| 新人独立接待达标周期 | 6～8 周（经验值） | ≤ 4 周 | 首次通过达标线（总分 ≥ 80）的日期 |
| 高频场景覆盖率 | 无统计 | ≥ 90% 高频场景被训练过至少 3 次 | 系统统计"咨询内容"被练次数 |
| 首次响应时长达标率 | 无统计 | ≥ 90% 的接待会话达标 | 评分报告统计 |
| 带教人均可覆盖新人数量 | 1～2 人 | ≥ 5 人 | 任务下发与明细报表统计 |
| 训练素材沉淀量 | 0 | ≥ 300 条咨询内容、≥ 100 个商品、≥ 500 个剧本 | 素材库统计 |

## 1.3 系统定位与边界

**系统定位**：面向企业内部客服培训的 PC Web 独立系统，不是真实客服工作台，不直接对接线上客户。

**本期边界（明确不做）**：

- 不与真实平台（抖店/千牛等）做数据接口对接，不读取真实会话与真实订单。
- 不接入任何大模型或 AI 服务，买家提问推送、追问触发、回复判定与评分全部由"剧本数据 + 规则引擎"实现（详见 5.9 节的接口预留说明）。
- 不提供移动端 APP，不提供多租户 SaaS 能力。
- 不提供通话（语音）客服训练，仅覆盖文字在线接待。

# 2 总体设计

## 2.1 系统总体形态

系统为浏览器访问的 PC Web 应用，使用 Chrome / Edge 最新版浏览。整体分为三类页面：训练类页面（在线模拟接待）、管理类页面（剧本、商品、案例、任务、风格、账号）、分析类页面（模拟接待明细）。

页面的视觉与信息结构以抖店客服工作台为蓝本：接待页采用"左侧会话队列 + 中间对话区 + 右侧订单/商品卡片与快捷短语"的三栏结构，让新人在训练阶段就形成与真实工作一致的操作肌肉记忆。

## 2.4 模块依赖关系

模块之间是"素材 → 生产 → 训练 → 沉淀 → 反馈"的依赖链，任一环节缺失都会导致训练质量下降：

| 上游模块 | 依赖关系 | 下游模块 |
| --- | --- | --- |
| 商品库 | 剧本必须关联至少一个商品，接待页右栏据商品数据渲染商品卡片 | 客户问题剧本、在线模拟接待 |
| 买家咨询背景 / 咨询内容 | 二者交叉组合生成剧本 | 客户问题剧本 |
| 沟通风格 | 剧本生成时按占比为每个剧本分配买家风格 | 客户问题剧本、在线模拟接待 |
| 客户问题剧本 | 接待开始时按难度抽取剧本，按顺序推送买家问题 | 在线模拟接待 |
| 回复模拟任务 | 限定本次接待使用的难度与剧本范围，并设定达标目标 | 在线模拟接待、模拟接待明细 |
| 在线模拟接待 | 产生接待会话与消息流 | 模拟接待明细 |
| 规则引擎 | 在接待过程中判定回复有效性、触发追问、计算得分 | 在线模拟接待、模拟接待明细 |
| 案例收藏 | 可转换为剧本，或作为评分的参考答案 | 客户问题剧本、模拟接待明细 |
| 模拟接待明细 | 沉淀训练档案，暴露薄弱场景 | 回复模拟任务（针对性补练） |
| 账号 | 提供身份、角色与系统参数 | 全部模块 |

一句话概括依赖链：**账号定义谁在练；商品库 + 背景 + 内容 + 风格生产出剧本；任务决定练什么；在线模拟接待把剧本演成一次真实对话；规则引擎给出评分；模拟接待明细把结果沉淀为档案；案例收藏把真实经验回流成新的剧本素材。**

## 2.5 核心业务闭环

1. **素材准备**：管理员维护商品库、买家咨询背景、买家咨询内容、沟通风格与快捷短语。
2. **剧本生产**：在《客户问题剧本》中按"背景 × 内容"批量生成剧本，系统按沟通风格占比自动分配买家风格，自定义剧本可手写对话脚本文本；也可从《案例收藏》导入的真实会话反向生成剧本。
3. **任务下发**：带教在《回复模拟任务》中设定难度、剧本范围、目标指标与截止时间，下发给指定客服或小组。
4. **模拟训练**：客服在《在线模拟接待》中开始接待，按难度并发接入 1～4 名模拟买家，在会话间切换、限时回复、使用快捷短语与商品卡片辅助应答。
5. **自动评分**：接待结束后规则引擎立即产出四维评分与结论（达标 / 未达标），记录到《模拟接待明细》。
6. **复盘改进**：客服与带教在明细中逐条回放对话、查看扣分点、添加批注；带教据此下发针对性补练任务，形成闭环。

## 2.6 关键设计原则

- **真实性优先**：接待页的布局、计时方式、会话切换、超时提醒均向抖店客服工作台看齐，避免"练一套、干一套"。
- **确定性可复现（一期核心约束）**：买家提问由剧本数据驱动，回复判定与评分由规则引擎计算，同样的剧本 + 同样的回复必须得到同样的结果，不依赖任何模型服务。
- **可配置**：所有时限、权重、达标线、分档阈值均为系统参数，业务可直接调整而不需要改代码。
- **双计分守恒**：多客户并发时，每个会话独立计分，接待任务总分取各会话的加权平均值，避免"会话数量越多总分越容易被稀释"。
- **训练与考核分离**：通过"自由练习"与"任务训练"两种入口区分"随便练"和"被考核"，前者不计入解锁进度与考核报表。
- **数据可追溯**：所有接待会话、消息、评分、批注均落库且不可篡改（修改只能通过新增记录实现），保证训练档案可信。

# 3 功能模块需求

本章逐个定义八大模块。每个模块统一按八个小节展开：定位与目标、使用角色、功能清单、关键字段与规则、页面与交互要点、与其他模块的关系、一期范围与二期演进、验收要点。

## 3.1 在线模拟接待

### 3.1.1 定位与目标

本模块是整个系统的训练主场景，目标是在与抖店客服工作台高度一致的界面中，让新人在**受控的、可复现的、可量化**的环境下练习在线客户回复。

核心目标：

- 支持 1～4 名模拟买家同时进线并发接待，训练新人的多会话切换与优先级判断能力。
- 严格按抖店客服工作台的计时口径记录首次响应时长、平均响应时长与超时次数，让训练压力贴近真实工作。
- 买家提问由剧本按顺序推送，配合沟通风格表现情绪与语气，避免"一问一答的机械练习"。
- 接待结束后立即给出结果判定（达标 / 未达标）并写入《模拟接待明细》，训练当即闭环。

### 3.1.2 使用角色

| 角色 | 在本模块中的行为 |
| --- | --- |
| 客服（新人） | 主要使用者。选择难度或接收任务，开始接待、切换会话、回复买家、结束会话 |
| 主管 / 带教 | 观战旁听（只读）、在接待结束后复盘批注 |
| 管理员 | 配置难度档位参数、计时阈值、并发上限 |

### 3.1.3 功能清单

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| F1-01 | 难度选择 | 四档难度：话术适应（1 名客户）、简单（2 名）、进阶（3 名）、困难（4 名） | 一期 |
| F1-02 | 训练入口区分 | 自由练习入口（任选难度、不计入解锁进度）与任务训练入口（由回复模拟任务带入） | 一期 |
| F1-03 | 并发客户进线 | 按难度在接待开始后按预设节奏依次进线，每名客户对应一个独立会话 | 一期 |
| F1-04 | 会话队列 | 左侧列表展示全部会话，含编号、买家昵称、咨询商品、等待/未读计时，可排序与分组 | 一期 |
| F1-05 | 会话切换 | 点击队列项切换当前会话，未读消息高亮提示，切换过程不丢失任何会话状态 | 一期 |
| F1-06 | 买家问题推送 | 按剧本顺序定时推送买家消息，支持追问、情绪化表达与"自问自答补充"（同一买家连发多条） | 一期 |
| F1-07 | 快捷短语 | 一键插入常用话术，支持变量替换（商品名、价格、订单号） | 一期 |
| F1-08 | 商品卡片 | 右栏展示当前会话咨询的商品卡片（主图、标题、商品ID、价格、规格），可插入到对话流发送给买家 | 一期 |
| F1-09 | 订单与售后卡片 | 右栏展示模拟订单信息（下单时间、金额、状态）与售后入口，供售后类剧本使用 | 二期 |
| F1-10 | 实时计时与超时提醒 | 每个会话独立计时，接近超时与已超时以颜色与提示音区分提醒 | 一期 |
| F1-11 | 会话结束与转交 | 客服可主动结束会话；剧本中标记为"需转交"的问题在客服点击转交后判定为正确处理 | 一期 |

### 3.1.4 关键字段与规则

**难度档位定义**：

| 档位 | 名称 | 并发客户数 | 默认单会话问题数 | 默认买家响应等待 | 默认解锁条件 |
| --- | --- | --- | --- | --- | --- |
| L1 | 话术适应 | 1 名 | 6～10 轮 | 宽松（超时阈值放大 1.5 倍） | 默认开放 |
| L2 | 简单 | 2 名 | 6～10 轮 | 标准 | L1 连续 2 次总分 ≥ 80 |
| L3 | 进阶 | 3 名 | 6～10 轮 | 标准 | L2 连续 2 次总分 ≥ 80 |
| L4 | 困难 | 4 名 | 6～10 轮 | 标准 | L3 连续 2 次总分 ≥ 80 |

难度设计的补充说明：

- **问题轮数统一**：四个档位的单个会话均为 6～10 轮，保证无论新人从哪一档开始练，单次对话的信息量与完整度一致，避免"低难度练得太浅、升档后不适应"。
- **响应等待口径**：仅 L1（话术适应）按宽松口径执行（超时阈值放大 1.5 倍），L2、L3、L4 均按标准口径执行，不再对高难度收紧响应阈值。
- **压力差异来源**：档位之间的压力差异主要由并发客户数（1→2→3→4）、买家进线节奏、剧本难度（售前 → 售前售后混合 → 售后/情绪化/连环追问）以及买家沟通风格分布决定，而非通过缩短响应时限制造紧张感。

**计时与考核规则（默认值，可在系统参数中调整）**：

| 指标 | 默认口径 | 计分方式 |
| --- | --- | --- |
| 首次响应时长 | 买家消息进入会话 → 客服首次回复的间隔 ≤ 30 秒 | 每次接待取所有会话的最大值参与计分 |
| 平均响应时长 | 单会话内每轮回复间隔的平均值 ≤ 60 秒 | 每会话独立计算，按会话加权到任务总分 |
| 3 分钟回复率 | 回复间隔 ≤ 180 秒的消息占比 ≥ 90% | 低于 90% 按档扣分 |
| 超时未回复 | 单条消息超过 180 秒未回复记为一次超时 | 每次超时扣响应时效分 |
| 接待上限 | 单次接待最多 4 个并发会话（对应 L4） | 超出上限不允许开始接待 |
| 进线节奏 | 第一名客户立即进线，其余按 10～30 秒随机间隔进线 | 进线节奏可在难度参数中配置 |

> 说明：**平均响应与超时判定的官方口径已取得**（2026-10-02，抖店学习中心），公式为
> 「飞鸽平均响应时长 = 近 30 天工作时间消费者与商家飞鸽对话轮次的回复时长之和 ÷ 近 30 天工作时间人工咨询对话轮次总数」，
> 只考核每天 8:00:00–22:59:59 发起的人工客服会话（含智能客服转人工，纯智能客服会话不考核）；
> 未回复的轮次记 **600 秒**；消极敷衍回复判为无效回复，后续有有效回复则本轮记「用户发消息到首条有效回复」的时长，
> 仍无有效回复则记 600 秒（2026-09-29 起生效）。
> **官方没有公布「≤ N 秒」的合格线**——上表中的 60 秒是本项目自填的默认值，可在《账号 → 系统参数 → 考核规则》中调整，无需改代码。
> 来源：school.jinritemai.com/doudian/web/article/aJYrJhaZXdL1（体验分指标说明-飞鸽平均响应时长）、/103956（商家体验分规范）、/aJqQgPuh9FqV（飞鸽敷衍回复预警）。

**会话状态机**（单个会话独立流转）：

| 状态 | 含义 | 可迁移到 |
| --- | --- | --- |
| 等待接入 wait | 买家已进线、尚未被客服打开 | 接待中 |
| 接待中 serving | 正常对话中 | 等待买家回复、已结束、超时 |
| 等待买家回复 waiting_buyer | 客服已回复，等待剧本下一轮问题推送 | 接待中、已结束 |
| 超时 timeout | 超过超时阈值未回复（可恢复，恢复到接待中） | 接待中、已结束 |
| 已结束 finished | 会话正常结束 | 终态 |
| 已转交 transferred | 需转交的会话被正确转交 | 终态 |
| 异常中止 aborted | 接待被强制中断（浏览器崩溃、超时放弃） | 终态 |

**接待任务（attempt）汇总规则**：

- 每个会话独立计算得分；接待任务总分 = 各会话得分的加权平均值，权重默认按"该会话的问题轮数"加权。
- 只有全部会话都进入终态，接待任务才生成结果页与明细记录。
- 若存在"异常中止"的会话，该会话按 0 分计入，并在结果页明确标注原因。

### 3.1.5 页面与交互要点

接待页采用三栏结构，与抖店客服工作台保持一致：

- **左侧会话队列（约 300px）**：顶部为统计区（接待买家总数、正在接待、已结束、转交），下方为搜索框与"正在接待 / 接待结束"两个页签，列表项展示序号徽标、买家昵称、咨询商品标签、等待计时或未读红点；点击切换会话，未读会话以红点与加粗提示。
- **中间对话区（自适应）**：顶部为当前买家的身份信息与备注入口，中部为消息流（买家消息左对齐、客服消息右对齐，商品卡片以富文本卡片形式内嵌），底部为输入区与工具栏（表情、图片、快捷短语、商品卡片、转交、结束会话），支持 Enter 发送、Ctrl+Enter 换行。右侧以醒目的倒计时提示当前会话距离超时还剩多少秒。
- **右侧信息区（约 380px）**：包含"订单 / 商品 / 快捷短语"三个页签；商品页签展示"咨询宝贝"卡片，提供邀请下单、计算价格、规格属性、商品视频、商品评价等动作按钮；快捷短语页签按分类列出可一键插入的话术。
- **顶部状态条**：显示当前难度、剩余会话数、接待已用时长、任务名称（若为任务训练）。

关键交互细节：

- 买家消息到达时，若不在当前会话，队列项显示未读红点并播放轻提示音；超过 30 秒未处理升级为橙色，超过 180 秒升级为红色并计入超时。

- 结束后进入结果页，展示每个会话的得分卡、失分点列表与"查看明细""再来一次"入口。

### 3.1.6 与其他模块的关系

- 依赖《客户问题剧本》提供买家问题序列，依赖《商品库》提供商品卡片数据，依赖《沟通风格》决定买家语气与情绪。
- 若从《回复模拟任务》入口进入，则难度、剧本范围与达标目标由任务决定，客服不可修改。
- 产生的接待会话与消息全部写入《模拟接待明细》，由该模块展示与复盘。
- 接待结果反向影响《客户问题剧本》的"被练次数 + 平均得分"统计，帮助管理员发现"人人都会错"的剧本。

### 3.1.7 一期范围与二期演进

- **一期**：F1-01～F1-06、F1-07（基础版）、F1-08、F1-10～F1-13。
- **二期**：订单/售后卡片（F1-09）、接待备注（F1-14）、实时提示开关（F1-15）、语音朗读买家消息。

### 3.1.8 验收要点

- 四档难度均可正常开局，并发客户数与进线节奏符合难度定义。
- 会话切换后各会话的计时、消息、状态互不干扰，切回时进度与切换前一致。
- 首响、平均响应、3 分钟回复率、超时次数四项指标与服务端记录一致，误差为 0 秒。
- 刷新页面或断网 30 秒后重连，接待进度与计时不丢失（允许计时继续走）。
- 全部会话结束后 3 秒内生成结果页与明细记录。

| 主管 / 带教 | 查看本组全部记录；批注、标记典型问题、导出 |

### 3.2.6 与其他模块的关系

- 数据来自《在线模拟接待》，是训练的沉淀结果。
- 为《回复模拟任务》提供任务达成情况与整组统计。
- 可把某次接待标记为典型案例并推送到《案例收藏》；也可从明细中直接跳转查看所用剧本。
- 明细中暴露的高频失分剧本，会反向提示管理员优化《客户问题剧本》的"期望回复要点"配置。

### 3.2.7 一期范围与二期演进

- **一期**：F2-01～F2-05。
- **二期**：F2-06～F2-09。

### 3.2.8 验收要点

- 明细列表数据与接待结果页完全一致，包括总分与结论。
- 回放内容与接待过程逐条一致，消息顺序、时间戳、耗时均正确。
- 批注权限正确：客服只能批注本人记录，带教可批注本组记录。
- 筛选与排序结果准确，分页与总数统计正确。

## 3.3 客户问题剧本

### 3.3.1 定位与目标

本模块是训练内容的生产工厂。系统把"买家为什么来问"和"买家问什么"拆成两类可复用素材，再通过交叉组合批量生成剧本，使新人能练到同一问题在不同买家背景下的差异化回答。

三层结构：

- **买家咨询背景**：买家的动机与画像（使用场景、品牌偏好、消费能力、送礼需求等）。
- **买家咨询内容**：买家的具体问题与可接受的回复方案（模板名称、买家咨询问题、图片、买家接受方案）。
- **剧本**：背景 × 内容 × 商品 × 沟通风格 的组合产物，是接待模块可直接调用的训练单元。

### 3.3.2 使用角色

| 客服（新人） | 只读查看剧本（用于预习），不能编辑 |

## 3.6 回复模拟任务

### 3.6.4 关键字段与规则

**达成判定规则**：

## 3.7 沟通风格

### 3.7.1 定位与目标

同一个问题，友善随和的买家和急躁易怒的买家需要完全不同的应答方式。本模块通过为模拟买家配置沟通风格与聊天占比，让剧本"活起来"：同一批剧本可自动生成不同性格的买家，训练新人的应变与情绪安抚能力。

配置对象是**模拟买家**，不用于客服侧的话术模板。

### 3.7.2 使用角色

管理员维护风格字典与默认占比；主管在创建剧本时可调整占比；客服在接待中感受风格差异，不参与配置。

### 3.7.3 功能清单

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| F7-01 | 风格字典维护 | 维护风格名称、风格描述、语气示例、情绪基线 | 一期 |
| F7-02 | 聊天占比配置 | 以"多行风格 + 占比%"的形式配置，支持增删行 | 一期 |
| F7-03 | 占比校验 | 总和不得大于 100%；未填写的行按剩余比例平均分配 | 一期 |
| F7-04 | 风格生效 | 剧本生成时按占比随机分配风格，接待中按风格影响消息语气与情绪值 | 一期 |
| F7-05 | 情绪值机制 | 急躁类买家带初始情绪值，客服安抚话术可降低情绪值，情绪值过高触发升级追问 | 一期 |
| F7-06 | 风格与难度绑定 | 高难度档位提高急躁/纠结类风格的出现概率 | 一期 |
| F7-07 | 风格效果统计 | 统计各风格的达标率，识别最难应对的买家类型 | 二期 |
| F7-08 | 自定义风格模板 | 管理员可新增自定义风格（超出内置五种） | 二期 |

### 3.7.4 关键字段与规则

**内置风格字典**：

| 风格 | 特征描述 | 语气示例 | 情绪基线 | 默认占比 |
| --- | --- | --- | --- | --- |
| 友善随和型 | 语气客气、容易接受解释，偶尔闲聊 | "好的呢，谢谢亲～" | 低（0～20） | 30% |
| 急躁易怒型 | 语气急促、常用感叹号、容易升级为投诉 | "到底什么时候发？我都等了三天了！" | 高（50～80） | 15% |
| 直爽高效型 | 只问关键点，不喜欢寒暄，要求明确答案 | "直接说能不能今天发。" | 中（20～40） | 20% |
| 纠结谨慎型 | 反复确认细节，关注风险与售后 | "如果收到不合适，退货麻烦吗？会不会扣运费？" | 中（30～50） | 20% |
| 沉默寡言型 | 回复极短，需要客服主动引导 | "嗯。""多少钱？" | 低（10～30） | 15% |

**占比配置规则**：

- 每一行由"风格 + 占比%"组成，占比为 0～100 的整数。
- 占比总和必须 ≤ 100%；超过 100% 时保存被拦截并提示超出的数值。
- 未填写占比的行按"剩余比例 ÷ 未填写行数"平均分配；全部未填写时按等分处理。
- 生成剧本时按占比进行加权随机分配，同一批次内尽量均匀覆盖各风格（避免小样本下某风格完全缺席）。
- 高难度档位（L3、L4）在抽取剧本时，将急躁易怒型与纠结谨慎型的权重上浮 1.5 倍。

**情绪值机制**：

- 每个会话维护 0～100 的情绪值，由风格基线初始化。
- 客服回复命中"安抚类关键词库"（如"理解""抱歉""马上为您处理""放心"）时情绪值下降 10～20。
- 客服回复出现"负面词库"内容（如"没办法""不知道""你自己看"）或连续两次未正面回应时，情绪值上升 15～25。
- 情绪值 ≥ 80 时买家触发升级追问（例如"我要投诉""叫你们主管出来"），若客服未在 60 秒内有效安抚，则该会话"情绪安抚"维度得分为 0。

### 3.7.5 页面与交互要点

风格配置页以行式表格维护（对应图 5）：

- 每行包含：买家沟通风格（下拉选择）、聊天占比（数字输入 + "%"）、删除图标（垃圾桶）。
- 底部提供"新增一行"按钮；建议行数 3～8 行。
- 保存时即时校验占比总和，超限时在页面顶部给出红色提示并高亮超限行。
- 右侧提供"本次将生成的风格分布预览"，以百分比条展示按当前占比生成的 100 个剧本中每种风格的数量。

# 4 关键业务规则汇总

本章把分散在各模块中的规则集中定义，作为开发实现与测试验收的唯一口径。

## 4.1 会话状态机

单个会话独立流转，状态定义见 3.1.4 节；完整的状态迁移规则如下：

| 当前状态 | 触发条件 | 目标状态 | 副作用 |
| --- | --- | --- | --- |
| wait 等待接入 | 客服点击该会话 | serving 接待中 | 开始计算首次响应时长 |
| wait 等待接入 | 进线后 180 秒内未被点击 | timeout 超时 | 记录一次超时，队列项标红 |
| serving 接待中 | 客服发送回复且剧本还有下一轮问题 | waiting_buyer 等待买家回复 | 记录本轮响应耗时 |
| serving 接待中 | 客服点击结束会话 | finished 已结束 | 未推送问题按未解决计分 |
| waiting_buyer | 剧本下一轮问题推送到达 | serving 接待中 | 买家消息未读提醒 |
| timeout 超时 | 客服回复 | serving 接待中 | 保留已记录的超时次数 |
| serving / waiting_buyer | 客服点击转交且该会话标记为需转交 | transferred 已转交 | 该会话按正确处理计分 |
| serving / waiting_buyer | 剧本问题全部推送完毕且买家发送结束语 | finished 已结束 | 触发评分计算 |
| 任意非终态 | 浏览器关闭或断线超过 60 秒 | aborted 异常中止 | 该会话按 0 分计入接待任务 |

接待任务（attempt）状态：`未开始 → 进行中 → 已结束`；只有全部会话进入终态后，接待任务才进入"已结束"并生成结果页。

## 4.2 计时与考核口径

| 计时项 | 起点 | 终点 | 默认阈值 | 说明 |
| --- | --- | --- | --- | --- |
| 首次响应时长 | 会话进入 wait 或被推送买家消息 | 客服首次发送回复 | ≤ 30 秒 | 按会话独立计算，取本次接待所有会话的最大值参与计分 |
| 单轮响应时长 | 买家消息进入会话 | 客服对该轮的首条回复 | ≤ 60 秒 | 同一轮多条回复只计首条；首条若被判无效回复，回退到该轮首条有效回复 |
| 平均响应时长 | — | — | ≤ 60 秒 | 按轮次加权：Σ轮次回复时长 ÷ 轮次总数（跨会话汇总）；未回复的轮次记 600 秒并计入分子 |
| 3 分钟回复率 | — | — | ≥ 90% | 回复间隔 ≤ 180 秒的轮次占比 |
| 超时次数 | 买家消息进入会话 | 超过 180 秒仍未回复 | 0 次 | 每次超时扣响应时效分 3 分 |
| 接待总时长 | 第一名买家进线 | 最后一个会话结束 | 不设硬上限 | 用于明细展示与统计 |

计时实现要求：**由服务端计算并下发**，前端仅做展示。前端每秒向服务端同步一次进度，断线重连后以服务端时间为准，避免通过修改本地时间或刷新页面规避超时记录。

**平均响应的官方口径（2026-10-02 取得，抖店学习中心）**

1. **按轮次加权**：平均响应 = Σ（每轮回复时长）÷ 轮次总数，跨会话汇总；对应实现见 `backend/src/domain/response-rounds.ts`。
2. **未回复记 600 秒并计入分子**（该轮仍计入分母）。官方原文：未回复本轮记 600 秒。
3. **无效回复回退**：一轮里首条回复若被判为无效回复，本轮时长回退到「用户发消息 → 首条有效回复」；始终没有有效回复的轮次记 600 秒。
   无效回复判定（重复 / 敷衍词表 / 连续 N 轮未命中要点）默认关闭，可在系统参数 → 无效回复判定中开启，见 `backend/src/domain/reply-validity.ts`。
4. **不引入时间窗**：官方按「近 30 天工作时间」统计，本训练系统不切时间窗（训练是单次接待），合格线保持系统参数可配。

> 措辞澄清：官方**没有**公布「≤ 60 秒」这类合格线，本项目的 60 秒是自填默认值。

## 4.3 评分维度与算法

总分 100 分，由四个维度构成，权重可在系统参数中调整（默认如下）。单次接待的最终得分 = 四个维度得分之和，保留一位小数。

**维度一：响应时效（40 分）**

| 子项 | 满分 | 计分规则 |
| --- | --- | --- |
| 首次响应 | 15 | ≤ 30 秒得 15 分；每超出 10 秒扣 2 分，扣完为止 |
| 平均响应 | 15 | ≤ 60 秒得 15 分；每超出 15 秒扣 2 分，扣完为止 |
| 3 分钟回复率 | 10 | ≥ 90% 得 10 分；每低 5 个百分点扣 2 分，扣完为止 |
| 超时惩罚 | — | 每次超时额外扣 3 分，本维度最低 0 分 |

**维度二：问题解决率（35 分）**

- 每个剧本问题满分为 `35 ÷ 本次会话问题总数`。
- 每个问题按其"期望回复要点"的命中比例判定：

| 要点命中比例 | 判定 | 得分 |
| --- | --- | --- |
| ≥ 80% | 已解决 | 该问题满分 |
| 40%～79% | 部分解决 | 该问题满分的 60% |
| < 40% | 未解决 | 0 分 |
| 答非所问（命中 0 个要点且语义无关） | 未解决 | 0 分 |

- 要点命中采用"关键词 + 同义词库"匹配，管理员可在《客户问题剧本》中为每个问题维护要点关键词。
- 需转交的问题，客服正确点击转交即视为已解决。

**维度三：话术规范（15 分）**

| 子项 | 分值 | 判定 |
| --- | --- | --- |
| 开场问候 | 3 | 会话首次回复包含问候语（您好/在的/亲等） |
| 结束语 | 3 | 会话结束前包含结束用语（还有其他可以帮您吗/感谢咨询等） |
| 无禁用词 | 5 | 未出现禁用词库内容（如"不知道""没办法""你自己看"） |
| 无无效重复 | 4 | 同一话术连续发送不超过 3 次 |

**维度四：情绪安抚（10 分）**

- 仅对包含情绪化剧本（急躁易怒型、纠结谨慎型）的会话计分，按情绪值终值判定：

| 情绪值终值 | 得分 |
| --- | --- |
| < 30 | 10 分 |
| 30～59 | 7 分 |
| 60～79 | 4 分 |
| ≥ 80 | 0 分 |

- 若本次接待中所有会话均为非情绪化剧本，则该维度按 **10 分满分**计入，并在评分报告中标注"本次无情绪化场景"（该行为可配置）。

**多会话加权**：

接待任务总分 = Σ(会话得分 × 会话权重) ÷ Σ(会话权重)，权重 = 该会话的剧本问题轮数（最少按 1 计）。该规则避免"会话越多总分越容易被稀释"，也避免"只做好一个简单会话就拿高分"。

## 4.4 难度解锁规则

| 规则项 | 定义 |
| --- | --- |
| 解锁判据 | 同一难度档位连续 2 次接待达标（任务总分 ≥ 达标线，默认 80） |
| "连续"的定义 | 该难度最近 2 次接待均达标；中间出现未达标则重新计数 |
| 开放方式 | 满足判据后自动解锁下一档，并在首页提示"已解锁简单难度" |
| 自由练习 | 任意难度均可直接选择开始，但结果标记为"自由练习"，不计入解锁进度、不进入考核报表 |
| 任务训练 | 通过《回复模拟任务》进入的接待，结果计入解锁进度 |
| 管理员特权 | 管理员与带教可直接为客服开放指定难度（用于特殊安排） |

## 4.5 剧本抽取与商品关联规则

- **抽取数量**：等于难度档位的并发客户数（L1=1，L2=2，L3=3，L4=4）。
- **去重规则**：同一次接待内不重复使用同一"买家咨询内容"，保证训练场景不重复。
- **优先规则**：优先抽取该客服"被练次数最少"的剧本，兼顾覆盖度与公平性。
- **难度匹配**：四个档位统一抽取 6～10 轮的剧本（与 3.1.4 节一致）；L1 优先抽取售前剧本，L2 抽取售前/售后混合剧本，L3、L4 优先抽取售后、情绪化与连环追问剧本。
- **轮数不足的兜底**：若可用剧本的提问序列不足 6 轮，系统在接待时从该剧本的补充追问池自动补足至 6 轮；若仍不足，则按实际轮数执行，并在《模拟接待明细》中标注"轮数不足"，同时提示管理员补充剧本。
- **任务限定**：任务训练时严格在任务设定的剧本范围内抽取，范围不足时允许重复内容并在结果页提示。
- **商品关联**：每个剧本至少关联 1 个商品；接待页右栏展示当前会话所关联商品的卡片；同一剧本关联多个商品时随机取其一，保证同批次训练的商品多样性。
- **售后剧本**：售后类剧本额外启用订单卡片数据（模拟订单号、下单时间、金额、状态）。

## 4.6 沟通风格占比规则

- 占比为整数百分比，总和不得超过 100%，超出时保存被拦截。
- 未填写的行按剩余比例平均分配；全部未填写时按等分处理。
- 按占比加权随机分配风格，并保证同一批次内小样本下的均匀性（生成 N 个剧本时，各风格数量与理论值的偏差不超过 ±5%）。
- 高难度档位下，急躁易怒型与纠结谨慎型的抽取权重上浮 1.5 倍。
- 已生成的剧本可手工覆盖其风格，手工值优先于占比分配结果。

## 4.7 会话结束与结果判定规则

| 场景 | 判定 |
| --- | --- |
| 剧本问题全部推送完毕，客服给出最终回复，买家发送结束语 | 正常结束，按四维评分 |
| 客服在剧本未推送完毕时点击"结束会话" | 提前结束，未推送问题按未解决计 0 分，结果页标注"提前结束" |
| 需转交的问题被客服正确转交 | 该会话以"已转交"结束，问题解决率按已解决计分 |
| 客服未转交而直接结束 | 该问题按未解决计分 |
| 断线超过 60 秒 | 会话异常中止，按 0 分计入，结果页标注原因 |
| 接待任务总分 ≥ 达标线 | 结论"达标"，计入难度解锁与任务达成次数 |
| 接待任务总分 < 达标线 | 结论"未达标"，不计入解锁进度，可立即重练 |

## 4.8 异常与边界规则

- 消息内容为空、纯表情、纯符号时不允许发送，前端提示"请输入有效回复"。
- 单条消息长度上限 500 字，超出时禁止发送并提示。
- 同一话术连续发送 3 次以上，触发"无效重复"判定并扣分。
- 命中禁用词库立即记录，在明细中高亮并在话术规范维度扣分。
- 接待过程中刷新页面、切换浏览器标签不影响计时；关闭浏览器超过 60 秒视为异常中止。
- 剧本被停用时，正在进行的接待继续完成，不受影响。
- 系统参数（阈值、权重、达标线）修改后立即对新接待生效；历史记录按生成时的参数快照计分，不重算。
- 同一账号同一时间只允许进行一个接待任务；已在进行中时，新的开始请求被拒绝并提示"请先结束当前接待"。

## 5.2 总体架构

系统采用前后端分离的四层结构：

| 层次 | 职责 | 关键实现 |
| --- | --- | --- |
| 表现层（Web） | 页面渲染、交互、实时消息展示 | React + Ant Design；接待页三栏布局；WebSocket 客户端 |
| 应用层（API） | 用例编排、权限校验、DTO 校验 | NestJS Controller + Service；JWT 鉴权；角色守卫 |
| 领域层（Domain） | 核心业务规则：计时、抽取、评分、情绪值、解锁 | 独立 RuleEngine 模块，纯函数实现，便于单元测试 |
| 数据层（Data） | 持久化、缓存、文件存储 | PostgreSQL + Redis + 本地/对象存储（图片） |

数据流：

1. 客服点击"开始接待" → 应用层校验权限与并发限制 → 领域层抽取剧本、创建 attempt 与 N 个 session → 写入数据库 → 通过 Redis 注册计时器。
2. 计时器到点 → 应用层通过 WebSocket 向该客服推送买家消息 → 前端渲染并更新未读提示。
3. 客服发送回复 → 应用层落库 → 领域层计算本轮响应耗时、更新情绪值、判定问题解决情况 → 返回本条消息的判定结果（前端可选择展示"已回应"提示）。
4. 会话结束 → 领域层计算四维得分 → 落库 → 推送结果给前端。
5. 全部会话结束 → 计算接待任务总分与结论 → 生成明细记录 → 更新剧本统计与解锁进度。

| 实体 | 说明 | 主要关系 |

| role 角色 | 权限集合 | 与 account 多对一 |
| group 小组 | 组织单元 | 包含多个 account |
| product 商品 | 商品主数据 | 与 script 多对多（script_product） |
| buyer_bg 买家咨询背景 | 素材 | 与 script 一对多 |
| buyer_qa 买家咨询内容 | 素材 | 与 script 一对多 |

| style 沟通风格 | 风格字典 | 与 script 多对一 |

实体关系的核心约束：

- 一个 attempt 至少包含 1 个 session，最多 4 个。
- 一个 session 有且仅有一个 script，一份 score。
- score 一旦生成不可修改，只能通过新增批注补充说明。
- script 被 attempt 引用后不可删除，只可停用。

## 5.5 实时并发接待设计

**核心难点**：多个会话同时计时、消息按节奏推送、断线后可恢复、前端不能成为计时权威。

设计方案：

- 每个 attempt 在 Redis 中维护一份状态：`attempt:{id}` 存储各 session 的状态、当前问题序号、下次推送时间、计时起点。
- 买家消息推送采用 Redis 有序集合（ZSET）实现延迟队列：`schedule:{claimTime}` 写入待推送任务，后台 worker 按秒扫描并触发。
- 计时由服务端计算，前端每 1 秒通过 WebSocket 发送心跳，服务端回传各会话的实时耗时与剩余超时秒数。
- 消息推送、超时提醒、会话结束均通过 WebSocket 广播到该客服的专属房间 `user:{accountId}`。
- 断线重连时前端调用 `GET /api/receptions/{id}/snapshot` 拉取全量状态，保证画面与服务端一致。

**WebSocket 消息类型**：

| 消息类型 | 方向 | 载荷要点 |
| --- | --- | --- |
| reception.ready | 服务端 → 客户端 | attemptId、难度、会话列表、准备倒计时 |
| customer.joined | 服务端 → 客户端 | sessionId、买家昵称、商品信息 |
| buyer.message | 服务端 → 客户端 | sessionId、消息内容、问题序号、情绪值 |
| timer.tick | 服务端 → 客户端 | 各会话已等待秒数、剩余超时秒数 |
| timeout.warning | 服务端 → 客户端 | sessionId、已超时秒数 |
| agent.message.ack | 服务端 → 客户端 | 消息落库结果、本轮耗时、情绪值变化 |
| session.finished | 服务端 → 客户端 | sessionId、结束原因、该会话得分 |
| reception.finished | 服务端 → 客户端 | attemptId、总分、结论、明细链接 |
| client.ack | 客户端 → 服务端 | 心跳、已读会话、当前会话切换 |

## 5.6 规则评分引擎设计

评分引擎是本期"机器人"的核心，采用策略模式实现，每个维度一个 Strategy，便于按需调整权重与算法：

```
ScoreEngine
 ├── ResponseTimeStrategy      // 响应时效 40 分
 ├── ProblemSolvingStrategy    // 问题解决率 35 分
 ├── WordingStrategy           // 话术规范 15 分
 └── EmotionStrategy           // 情绪安抚 10 分
```

实现要点：

- **纯函数设计**：输入为"会话消息序列 + 剧本期望要点 + 系统参数快照"，输出为各维度得分与失分明细，不访问数据库，便于单元测试与回归。
- **关键词匹配**：每个问题维护要点关键词数组，命中即计为满足该要点；提供同义词库（如"包邮/免运费/不额外收费"）提升鲁棒性。
- **参数快照**：评分时把当时的权重、阈值、达标线写入 score 表，保证历史结果可解释、不随参数调整而改变。
- **失分明细**：每个扣分项生成一条明细记录（扣分原因、涉及消息、扣分值），用于明细页展示。

## 5.7 剧本生成与抽取算法

**批量生成**：

1. 输入：背景集合 B（n 条）、内容集合 Q（m 条）、商品集合 P、风格占比表 S、接待类型 T。
2. 输出 n × m 个剧本，对每个 (bg, qa) 组合：
   - 剧本名称 = `{T} - {bg 简称} - {qa 模板名}`；
   - 关联商品 = P 中按"适用场景匹配度"排序后取前若干个（默认取全部）；
   - 风格 = 按 S 加权随机分配，并做去偏处理保证分布接近理论值；
   - 提问序列 = 由 qa 的"买家咨询问题"按分号拆分。
3. 生成结果以事务写入，失败整体回滚；生成超过 100 条时改为异步任务并返回任务 ID。

**接待抽取**：

1. 过滤：状态=启用、接待类型符合难度要求、任务范围（若有）内、商品上架。
2. 排序：按该客服对剧本的"被练次数"升序 → 被练次数相同时按"最近一次练习时间"升序（越久没练越优先）。
3. 去重：同一"买家咨询内容"只能出现一次。
4. 难度加权：L3/L4 对售后、情绪化、多问题剧本加权。
5. 兜底：候选不足时允许重复内容，并在结果页提示"本次存在重复场景"。

## 5.9 后续可替换的机器人接口预留

> **一期明确不接入任何 AI 或大模型服务。** 本节描述的是为二期预留的扩展点，一期只实现接口定义，不实现任何模型调用。

- 定义统一接口 `BuyerAgentPort`，包含三个方法：`nextQuestion(context)`（生成下一个买家问题）、`reactToReply(context, reply)`（生成买家对客服回复的反应）、`evaluate(context, reply)`（对回复打分）。
- 一期实现：`RuleBasedBuyerAgent`，全部逻辑取自剧本数据与规则引擎，行为完全确定、可复现。
- 二期可选实现：`LlmBuyerAgent`，接入大模型以增强真实感；接入时保持接口不变，通过配置切换，并保留"考核模式必须使用规则实现"的约束，确保考核结果可复现、可申诉。
- 数据合规：若二期接入外部模型服务，需脱敏后再发送，禁止上传真实客户手机号、订单号、地址等敏感信息。

# 8 分期实施路线

## 8.1 一期（MVP）

**目标**：跑通"素材 → 剧本 → 接待 → 评分 → 明细"的最小可用闭环，让新人可以真实练起来。

一期交付范围：

| 模块 | 一期范围 |
| --- | --- |
| 在线模拟接待 | 四档难度、并发接待、会话切换、计时与超时提醒、快捷短语、商品卡片、结束与结果判定、断线续接 |
| 客户问题剧本 | 背景库与内容库管理、分类树、单个与批量生成剧本、接待类型、关联商品、剧本预览与启停 |
| 商品库 | 商品全字段维护、分类与搜索、批量导入、关联剧本查看 |
| 模拟接待明细 | 明细列表与筛选、评分报告、会话回放、人工批注 |
| 沟通风格 | 五种内置风格、聊天占比配置与校验、情绪值机制、风格生效 |
| 账号 | 登录、账号与角色管理、小组、个人资料、修改密码、系统参数、快捷短语 |
| 案例收藏 | 仅入口占位，不实现 |
| 回复模拟任务 | 仅入口占位，不实现 |

一期首页提供：我的训练进度（已解锁难度、最近 5 次得分）、快速开始（四档难度入口）、我的成绩概览。

## 8.2 二期

**目标**：补齐真实经验回流与训练管理闭环，把系统从"练习工具"升级为"训练管理体系"。

二期交付范围：

- 案例收藏：文件导入、文本粘贴导入、结构化、转剧本、优秀回复标记、案例检索、平台导出适配器。
- 回复模拟任务：任务创建与下发、目标指标、接待中任务卡、达成判定、任务报表与催办。
- 模拟接待明细增强：典型案例标记、对比视图、导出、个人成长曲线。
- 其他：订单与售后卡片、接待备注、提示模式、剧本统计、操作日志、登录安全策略。

# 9 验收标准与测试要点

## 9.1 功能验收标准

| 模块 | 验收标准 |
| --- | --- |
| 在线模拟接待 | 四档难度可开局且并发数正确；计时与服务端一致；会话切换无状态丢失；断线 30 秒重连不丢数据；结束后 3 秒内出结果 |
| 客户问题剧本 | 4 背景 × 10 内容生成 40 个剧本且命名、商品、风格正确；被引用素材不可删除；停用剧本不再被抽取 |
| 商品库 | 全字段保存回显正确；100 条导入成功率 ≥ 99%；商品ID 重复正确跳过；下架商品不出现在新剧本选择中 |
| 模拟接待明细 | 明细与结果页数据一致；回放顺序与时间正确；批注权限正确；筛选排序准确 |
| 沟通风格 | 占比超 100% 被拦截；100 个剧本的风格分布偏差 ≤ ±5%；情绪值可升可降并触发升级追问 |
| 账号 | 三角色权限与权限矩阵一致；改权重后仅影响新接待；停用账号无法登录且历史保留 |

## 9.2 关键测试场景

**场景 1：四档难度并发接待**

- 分别以 L1～L4 开局，验证进线数量、进线间隔、右栏商品卡片、超时提醒阈值符合配置。

**场景 2：超时与计时准确性**

- 接待中故意不回复某一会话，验证在 180 秒时触发超时提醒、记录超时次数、扣 3 分，并在明细中正确回放。
- 通过刷新页面、切换标签、修改本地系统时间等方式尝试规避计时，验证服务端计时权威性。

**场景 3：问题解决率判定**

- 针对同一问题分别给出"完整回答""部分回答""答非所问""不回答"四类回复，验证命中比例判定与得分符合 4.3 节规则。

**场景 4：情绪安抚**

- 使用急躁易怒型剧本，验证客服使用安抚话术后情绪值下降、使用禁用词后情绪值上升、达到 80 后触发升级追问。

**场景 5：断线续接**

- 接待中关闭浏览器 30 秒后重开，验证快照恢复正确、计时连续；关闭 90 秒后重开，验证会话被标记为异常中止且计 0 分。

**场景 6：批量生成与抽取**

- 批量生成 40 个剧本后在接待中连续开局 10 次，验证不重复使用同一咨询内容、优先抽取被练次数少的剧本。

**场景 7：导入异常处理**

- 导入包含重复商品ID、价格非法、分类不存在的文件，验证失败清单的行号与原因准确。

## 9.3 性能与安全验收

| 类别 | 验收项 |
| --- | --- |
| 性能 | 50 人同时在线、其中 10 人同时进行 4 路并发接待时，消息推送延迟 ≤ 500ms，接口 P95 ≤ 500ms |
| 稳定性 | 连续运行 72 小时无内存泄漏；worker 重启后延迟队列任务不丢失 |
| 安全 | 越权接口返回 1003；密码不以明文存储；手机号脱敏；SQL 注入与 XSS 防护通过安全扫描 |
| 数据 | 接待消息与评分在同一事务内落库；数据库备份可成功恢复 |
| 兼容 | Chrome / Edge 最新两个版本下布局与交互正常，1366×768 分辨率下接待页可用 |
