> 观察时间：2026-10-03 14:08–14:15（抖店工作台 1.1.11 → 赤兔火眼 → 培训室 → 自由练习）

> 观察方式：由 Codex 真实操作完成**一整场**自由练习（10 个买家全部接待完毕），逐个记录左栏计数与队列变化

## 二、结论（实测）

1. **左栏四个计数**：`接待买家` / `正在接待` / `已结束` / `转交`，
   且全程满足 **接待买家 = 正在接待 + 已结束 + 转交**（例：6=3+3+0、9=3+6+0、10=0+10+0）。
   → `接待买家` 是**累计进线人数**，不是"本次要接待的总量"。
2. **没有「待接入」这一栏**：还没进线的买家在界面上完全不出现（不是排队列表），
   只有「正在接待(N) / 接待结束(N)」两个页签。
3. **补位是「空位即补」的流水式，不是「整批结束才换一轮」**：
   只要有 1 个买家结束（买家自己结束，或客服点会话头部的 ✕「关闭会话」主动结束），
   空出的名额会在**数秒内**被下一个买家补上，正在接待重新回到 3。
4. **补位延迟很短**：多次实测新买家进线时「等待时长」只有 **1～6 秒**
   （14:12:04 关闭 → 14:12:08 新买家已进线；14:12:36 关闭 → 新买家等待 4s）。
5. **名额用满即停止补位**：`接待买家` 达到 10（本次上限）之后，再结束会话也不再进新人
   （10/2/8 → 10/1/9 → 10/0/10 都保持 10）。
6. **结束条件**：10 个买家全部进入终态 → 弹出「本次培训已结束，请前往模拟接待明细查看培训结果」，
   右栏自动切到「质检 / 考评」，提示「系统正在智能质检中，请稍后查看质检结果」。
7. **客服可以主动结束会话**：会话头部 ✕ 关闭时会二次确认「买家提问未结束，确认要关闭吗？」；
   买家问完后底部会出现提示「当前买家咨询已结束，也可按 ESC 键或点击 结束会话」。

## 四、与我们系统的差异（需要拍板）

| 维度 | 赤兔火眼（实测） | 我们系统（当前实现） |
| --- | --- | --- |
| 未进线买家 | **不展示**（没有排队列表） | 左栏「待接入(N)」独立页签（2026-10-03 按客户反馈新增） |
| 补位时机 | **空位即补**（几秒内） | 2026-10-03 已按客户口径改成**整批结束才补**（`promoteWaiting` 里 `active > 0 就 return`） |
| 计数口径 | 接待买家 = 累计进线（不含未进线） | 接待买家 = 本次总接待人数（含未进线的排队买家） |
| 同时接待上限 | 自由练习设置里「最多同时接待 N 个买家」 | 系统参数「L1～L4 接入人数」+ 并发上限 |
| 客服主动结束 | 会话头部 ✕ → 二次确认 | 工具栏「结束当前会话」→ 二次确认（平台侧） |

> **一句话**：赤兔是「**3 个位置坐满，谁走了马上补谁**」；我们上一轮按客户口述改成了「**这一批全走完才换下一批**」。
> 两者对训练节奏的影响：赤兔的节奏更接近真实工单流水，新手会一直在"3 路并发"压力下；
> 整批换新的节奏会把压力切成一段一段。

## 五、客户决定（2026-10-03）与落地

客户看完本记录后拍板：**按赤兔口径改**——

1. **补位 = 空位即补**（有会话进终态就补一个待接入买家，几秒内进线）；
   实现：`reception.service.ts` 的 `promoteWaiting()` 按空位补满，并给新买家留 1.5～4.5 秒再推第一条问题。
2. **左栏「接待买家」= 累计已进线**（不含排队）；排队人数仍单独看「剩余会话 / 待接入」页签。
3. 去掉上一版为「整批换新」引入的轮次概念（`round_no` 与 `第N轮` 标签）。

验收：`client-requirements.e2e-spec.ts` 的 C5 空位即补用例、`reception.e2e-spec.ts` 重启恢复用例、
`npm run flow:check` 的「接待页 · C5 待接入与「接待买家=累计已进线」」。
