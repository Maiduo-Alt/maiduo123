# 本地语义判定

本地判定需要可处理问答上下文的轻量指令模型。现有 BGE 向量服务仍可供其他功能使用，但不参与本模式下的答复通过判定。

在服务器项目根目录执行：

```bash
compose=(sudo docker compose --env-file .env -f deploy/lighthouse/docker-compose.yml -f deploy/lighthouse/compose.semantic.yml -f deploy/lighthouse/compose.local-judge.yml --profile semantic)
"${compose[@]}" up -d --no-deps semantic-judge
"${compose[@]}" exec -T semantic-judge ollama pull qwen3:0.6b
"${compose[@]}" build api
"${compose[@]}" up -d --no-deps --wait api
```

首次启动需下载模型权重，推理在服务器内完成。自定义模型时，下载与 LOCAL_SEMANTIC_JUDGE_MODEL 一致的名称。先结束进行中的接待，再切换模式，使用新接待验证。模型不可用或返回无效证据时，回复可重试，不使用关键词代判。风险扣分、业务操作、开场和收尾继续由原流程处理。

如需以后恢复外部 API，在 Compose 的 API 环境变量中设置 REPLY_JUDGMENT_MODE=external 并配置现有密钥。此模式也不让关键词参与答复通过。省略模式变量会保留原有混合判定，便于兼容其他部署。
