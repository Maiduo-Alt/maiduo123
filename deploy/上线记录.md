## 上线过程中修掉的两个问题

1. **`.gitignore` 误排除源码**：`uploads/` 规则连源码目录 `backend/src/modules/uploads/` 一起排除了，
   导致远端仓库缺 3 个文件、云端 `tsc` 报 `TS2307`、Docker 构建失败。
   已改为锚定的 `/uploads/` 并加 `!/backend/src/modules/uploads/`。
2. **cloud SDK 的 SSL 兼容**：pg 8.23 把 `sslmode=require` 当作 verify-full，与 Node 24 组合会报
   `SELF_SIGNED_CERT_IN_CHAIN`；Supabase 连接串改用 `sslmode=no-verify`（仍全程加密）。
   `backend/src/db/db.service.ts` 也补了 `PG_SSL` 开关，便于换成其它托管库。

## 使用前请注意

- ⚠️ 默认测试域名（`*.webapps.tcloudbase.com`）首次访问会弹腾讯云**风险提醒**页，点「确定访问」继续；
  绑定自有域名后不再出现。
- ⚠️ 云托管「最小实例数」建议设为 `1`。设 0 时冷启动 + 国内到 Sydney 建连较慢，首屏可能超时。
- ⚠️ 云托管**无持久卷**，上传的商品图在重新部署后会丢；长期使用请改存 COS 或云存储。
- 🔐 三个演示账号（`admin` / `leader` / `agent`）口令请上线后尽快修改。
- 🔐 数据库密码与 `JWT_SECRET` 已在对话中传递过，建议轮换一次；换 `JWT_SECRET` 只会让所有人重登。

## 前端产物如何重新构建

后端域名变了以后，前端要带上新的 `VITE_API_BASE` 重新构建：

```powershell
cd frontend
$env:VITE_API_BASE='https://<云托管域名>'
$env:VITE_SOCKET_URL='https://<云托管域名>'
node ..\node_modules\typescript\bin\tsc --noEmit -p tsconfig.json
node ..\node_modules\vite\bin\vite.js build
```

然后把 `frontend/dist` 的内容打包成 zip（根目录直接是 `index.html`），
到 CloudBase「静态网站托管 → 本地项目上传 → 压缩包」上传，
**部署路径填 `/`**（产物用的是 `/assets/...` 绝对路径，部署到子路径会 404）。
